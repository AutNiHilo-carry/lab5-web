# Lab5 生产订单与物流管理系统

无人机整机生产的**生产订单与物流管理系统**，覆盖需求文档中的全部功能：
基础资料（工厂/车间/部门/仓库/供应商客户/物料…）、BOM 与工艺路线、
工单下达与派工报工、仓储单据与库存管理。

包含三部分：

| 部分 | 目录 | 说明 |
| --- | --- | --- |
| 前端 | `app/` + `index.html` | 零依赖静态页面，Vue 3 + Element Plus，**打开就能跑** |
| 数据库 | `db/` | MySQL 建库建表 + 初始化数据 + 存储过程 + 报表查询（24 张表） |
| 后端 | `server/` | Express + MySQL 的 REST 接口，含 60 项接口自检 |

## 一、怎么打开

**方式一（只跑前端，最简单）**：双击 `index.html`，用 Chrome / Edge 打开即可。

**方式二（推荐）**：双击 `启动系统.bat`，或执行：

```bash
node serve.mjs            # 前端 http://localhost:5173
```

> 不需要联网、不需要 npm install。`vendor/` 里已放好 Vue 3.5.13、Vue Router 4.4.5、
> Element Plus 2.8.8 的本地文件。

**方式三（跑后端 + 真实数据库，推荐用来演示"真数据库"）**：

数据库用真实 MySQL 8.0，第一次装库、之后每次启动：

```
安装数据库.bat      # 仅第一次：自动下载安装 MySQL 8.0.29（约 214MB，免管理员）
初始化数据库.bat    # 建库建表：执行 db/01~04（会重置 lab5_mes）
启动数据库.bat      # 每次开机后启动 MySQL（127.0.0.1:3307，root 空密码）
启动后端.bat        # Express 起在 http://127.0.0.1:3000
```

然后浏览器打开 <http://localhost:5173/?api=http://127.0.0.1:3000>，
页面会自动切到后端 + MySQL 的数据（详见 [server/README.md](server/README.md)）。

验证是否真的连上数据库：打开 <http://127.0.0.1:3000/api/health>，
看 `"repo"` 是 `mysql`（真库）还是 `memory`（降级）。

> 没有 MySQL 也能跑：`cd server && USE_MEMORY=true npm start`，或直接开 `index.html`
> 用浏览器本地数据。三套数据的业务规则是同一份代码。
>
> 发给别人：`node scripts/build-package.mjs` 会打出 `lab5-web-发给别人.zip`（约 2.7 MB，
> 自包含含 node_modules），对方解压后按包内 `使用说明.md` 三步走即可。

## 四、课堂演示建议流程（约 5 分钟）

1. **登录**：用 `planner`（李彦 · 计划员）登录。
2. **看板**：生产总览里有 1 张草稿工单、待确认单据、若干库存预警。
3. **基础资料**：工厂与车间里点"部门"页签，说明部门和车间是**平级**的、
   都挂在工厂下、各自有编号；再去"供应商与客户"看一张表里的两类单位。
4. **BOM 与工艺路线**：物料清单 BOM 里 `BOM-FG001-01` 的"工艺路线"列显示
   `RT-X4-01 四旋翼总装标准路线`——**路线自己不绑产品，是 BOM 指定用哪条**。
   打开工艺路线页看"使用该路线的产品"一列，可见同一条路线可被多个产品复用。
5. **建单**：生产工单 → 新建工单，填**工单名称**（如"X4 巡检机首批生产"）、
   选产品、数量 12、**负责工厂**、**主要车间** → 创建。系统自动生成编号。
6. **审核下达**：工单详情点"审核下达"，物料需求页签可见电机需求 = 4 × 12 = 48，
   工序任务页签可见 6 道工序（这是按 BOM 指定路线复制来的）。
7. **领料**：物料需求页签"一键生成领料单" → 到库存单据确认该草稿单，
   回来看到"已领用"数量和库存余额变化。
8. **派工 + 报工**：工序任务里派工选设备、工位、负责人，再报工填合格数；
   第二道工序的可报工数量受第一道合格数限制（现场试一下报超会报错）。
9. **成品入库**：末道报工完成后，工单详情右上角"生成成品入库单"，
   到库存单据确认，工单自动变"已完工"。
10. **库存**：仓储管理 → 库存余额，重点讲**这一页没有任何可填数量的输入框**：
    看到的是"累计入库 +、累计出库 −、当前结存"，库存只能由单据产生。
11. 演示完点右上角头像 → **重置演示数据**，恢复初始状态。

## 五、需求文档里的关键规则（已在代码中实现）

- 工单审核时，把 BOM 的单件用量 × 计划数量写入**工单物料需求**，
  把**BOM 指定的工艺路线**的工序复制成**工序任务**（之后改模板不影响已下达工单）。
- 派工信息（设备、工位、工装、负责人、计划时间）保存在**工序任务**上，不另建派工表。
- 报工数量不超过上一道工序移交的合格数。
- 在制品 = 前一道合格数 − 当前工序已处理数；待入库 = 末道合格数 − 累计入库数。
- **库存只能由单据产生**：草稿不动库存，确认后才按 +入库 / −出库 变动；
  出库库存不足不允许确认；退料不超过已领未退；成品入库不超过合格数；重复确认只生效一次。
- 确认单据时先整体校验再执行，避免"部分成功"。
- **库存没有初值**：余额 = 已确认单据的流水累加，页面上显示 +/− 汇总而非可填数字。
- **工艺路线不绑定产品**：路线是通用工序模板，由 `bom.routing_id` 指定；
  换工艺只改 BOM，同一条路线可服务多个产品。
- **工单既有名称又有编号**，并明确**负责工厂**（编号用于追溯，名称用于现场识别）。
- **部门与车间平级**，都挂在工厂下、都有唯一编号；用户按角色挂车间或部门。
- **供应商与客户**存在同一张表，用类型字段区分，一个页面加类型筛选。

## 六、目录结构

```
lab5-web/
├─ index.html              页面入口（引入 vendor 和 app 下的脚本）
├─ 启动系统.bat            一键启动（有 Node 起本地服务，没有就直接开网页）
├─ serve.mjs               零依赖本地静态服务
├─ vendor/                 Vue、Vue Router、Element Plus、图标、中文语言包
├─ app/
│  ├─ 00-core.js           工具函数（格式化、提示、标签颜色）
│  ├─ 10-db.js             数据层：24 张表结构 + 演示数据（localStorage 持久化）
│  ├─ 20-api.js            业务接口层：工单、报工、单据确认等全部业务规则
│  ├─ 21-api-rest.js       接后端的适配层（默认关闭，配一个地址即可切换）
│  ├─ 25-session.js        登录会话
│  ├─ 30-ui.js             通用组件（CRUD 页、状态标签、页面标题）
│  ├─ 40-layout.js         主框架（侧边菜单 + 顶栏）
│  ├─ 50~55-views-*.js     各业务页面
│  ├─ 60-app.js            路由与挂载
│  └─ style.css            自定义样式
├─ db/                     数据库：01 建表 / 02 数据 / 03 存储过程 / 04 视图与报表
├─ server/                 后端：Express + MySQL 接口（含自检）
└─ scripts/                自检脚本（不影响运行）
```

## 七、数据库（已建好，可直接执行）

`db/` 目录是完整的数据库设计，详见 [db/README.md](db/README.md)：

| 文件 | 作用 |
| --- | --- |
| `db/01-schema.sql` | 建库建表：24 张表、40 个外键、21 个唯一索引 |
| `db/02-data.sql` | 初始化数据（与前端演示数据逐行一致，**库存无期初值**） |
| `db/03-proc.sql` | 业务存储过程：审核下达、报工、确认单据 |
| `db/04-queries.sql` | 4 个视图 + 13 个常用报表查询 |

```bash
mysql -u root -p --default-character-set=utf8mb4 < db/01-schema.sql
mysql -u root -p --default-character-set=utf8mb4 < db/02-data.sql
mysql -u root -p --default-character-set=utf8mb4 < db/03-proc.sql
mysql -u root -p --default-character-set=utf8mb4 < db/04-queries.sql
```

## 八、后端（Express + MySQL，已实现）

`server/` 里有完整的 REST 实现，业务规则与数据库存储过程一一对应，详见
[server/README.md](server/README.md)：

```bash
cd server
npm install
USE_MEMORY=true npm start      # 无 MySQL 演示模式；有库就去掉这行
node test/api-test.mjs         # 60 项接口自检
```

前端切到后端只需一个地址（**页面代码不用改**）：

```js
MES.rest.enable('http://127.0.0.1:3000')   // 或在 URL 上加 ?api=http://127.0.0.1:3000
```

后端不可用时会自动退回 localStorage 演示模式，不影响任何演示。

## 九、自检脚本（可选）

```bash
# 前端
node scripts/check.mjs          # 语法检查
node scripts/compile-check.mjs  # 模板编译检查
node scripts/flow-test.mjs      # 端到端业务流程测试（建单→下达→领料→报工→入库）
node scripts/data-check.mjs     # 数据层检查：新表/新字段、库存无初值、BOM→路线
node scripts/asset-check.mjs    # 静态资源检查（需先 node serve.mjs）

# 数据库
node scripts/sql-check.mjs      # SQL 脚本自检（编码、表数、命名、外键顺序、业务规则）
node scripts/balance-check.mjs  # 库存余额与初始化数据一致性核对
node scripts/mysql-verify.mjs   # 真库检查：24 表/4 视图/3 过程/外键/utf8mb4/无期初（需 MySQL 已启动）
node scripts/proc-test.mjs      # 存储过程实测：审核下达、报工上限、单据确认（需 MySQL 已启动）

# 后端
cd server && node test/api-test.mjs        # 60 项接口检查（内存仓库 + 真实 HTTP）

# 前后端联调（需先启动数据库和后端）
node scripts/rest-test.mjs http://127.0.0.1:3000
```

> `mysql-verify.mjs` / `proc-test.mjs` 只读+少量写入，跑完可以用
> `01-schema.sql ~ 04-queries.sql` 重跑一遍把库重置回初始演示数据。
